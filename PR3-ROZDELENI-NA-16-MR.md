# BlockSci PR #3 – rozdělení na 16 MR

## Přehled

PR #3 (59 commitů, +5 348 / −422 řádků) je rozdělený do 16 MR pro crocs-muni/blocksci. Vysoké riziko mají tři: MR 11 a 12 rozbijí existující volání API a MR 16 mění pravidla JoinMarket detektoru. Po přeskládání se zatím žádný MR nepřekládal ani netestoval.

- **Zdroj:** větev `integration-coinjoin-detection-and-build` v `blocksci`, 58 commitů. Strom je shodný s `origin/master` a tip každého MR nese tag `mr/NN-<jméno>`. Větev i tagy `mr/*` jsou pushnuté na `origin` (OndrejMan/blocksci), žádný MR zatím neexistuje.
- **Řádky a soubory:** `git diff --shortstat` mezi tagem předchozího a daného MR. Součty (+5 386 / −460) dávají víc než PR #3, protože MR přidávají a mažou řádky v jiném pořadí než původní historie.
- **Riziko:** *Nízké* = oprava nebo doplněk, který nemění API ani výsledky analýzy. *Střední* = mění výsledky analýzy nebo postup buildu, API zůstává kompatibilní. *Vysoké* = rozbije existující volání API nebo mění pravidla detekce.

## Souhrn

Nejvíc pozornosti potřebují MR 11, 12 a 16, protože mění API nebo pravidla detekce. Ostatní MR opravují chyby nebo přidávají nové věci, ale část z nich posune výsledky analýzy.

- **Změny, které musí popis MR říct výslovně:** osobní fork testchain generatoru (MR 01, 13), povinný a přesunutý `coinjoin_type` (MR 11), subtyp Ashigaru `"250k"` → `"2.5m"` s jinou hodnotou a výjimky místo `false` (MR 12), zrušené vyloučení ostatních protokolů v JoinMarket detektoru (MR 16).
- **Posunuté výsledky analýzy:** MR 06 (unikátní adresy ve Wasabi 2), 07 (konsolidace), 08 (denominace Wasabi 2), 09 (`filter_coinjoin_txes`) a 10 (degradace anonymity) opravují chyby, ale čísla z dřívějších běhů s nimi nemusí sedět. Popis by měl uvést, kterým směrem se výsledky posunou.
- **Neověřené:** po přeskládání se žádný tag nepřekládal. Konflikty jsem řešil ručně v MR 04, 11, 12, 14, 15 a 16. Testy MR 13 počítají s přísnějším JoinMarket detektorem z MR 16. Před odesláním každého MR pustit Docker test stage (od MR 03) na jeho tagu.
